# garmin-mcp-readonly

[English](README.md) · **Українська**

Невеликий [MCP](https://modelcontextprotocol.io)-сервер, який дозволяє AI-асистенту **читати** твої власні дані з Garmin Connect: тренування, сон, HRV, готовність до тренувань, склад тіла, кроки.

Він працює як локальний процес на твоєму комп'ютері, входить в акаунт за OAuth-токенами, які ти отримав сам, і ніколи не просить і не зберігає твій пароль. Працює з будь-яким MCP-клієнтом, що вміє запускати локальний stdio-сервер; нижче інструкції для **Claude Code, Claude Desktop, OpenAI Codex і Google Antigravity**.

> **Неофіційний проєкт.** Він не пов'язаний із Garmin і не схвалений ними. Із Garmin Connect він спілкується через спільнотну бібліотеку [`garminconnect`](https://github.com/cyberjunky/python-garminconnect), яка використовує недокументовані ендпоінти. Вони можуть змінитися чи зламатися без попередження, а умови використання Garmin варто перевірити самостійно.

## Як це працює

```
Ти: «Як пройшла моя вчорашня пробіжка?»
   │
   ▼
Твій AI-клієнт (MCP-клієнт) ──stdin/stdout, JSON-RPC──▶ garmin-mcp (локальний процес Python)
                                                          │ server.py    обирає інструмент, розбирає дати, стискає відповідь
                                                          │ client.py    читає OAuth-токени з ~/.garminconnect
                                                          │ garminconnect ──HTTPS──▶ *.garmin.com
                                                          │ privacy.py   вирізає ідентифікатори та GPS
   ◀───────────────── компактний результат ───────────────┘
```

| Файл | Роль |
|---|---|
| `src/garmin_mcp/auth.py` (`garmin-mcp-auth`) | Одноразовий вхід, який ти запускаєш сам у терміналі. Питає email, пароль (прихований) і MFA-код, обмінює їх на OAuth-токени, після чого пароль відкидається. |
| `src/garmin_mcp/client.py` | Завантажує токени, тримає одну сесію Garmin протягом життя процесу, робить запити по одному (виклик чекає своєї черги не довше 30 с) і перетворює відомі помилки Garmin на короткі підказки. У ньому немає ні параметра, ні змінної середовища, ні конфігу, що приймали б пароль. |
| `src/garmin_mcp/server.py` | Інструменти MCP. Нормалізує дати (`today`, `yesterday`, `YYYY-MM-DD`) і зводить ~100 полів Garmin на одне тренування до ~15, які справді відповідають на запитання. |
| `src/garmin_mcp/privacy.py` | `scrub()` рекурсивно видаляє з кожної відповіді відомі ключі з ідентифікаторами акаунта чи пристрою та GPS-координати. |
| `tests/` | Юніт-тести, зокрема тести, що підтверджують твердження про безпеку з цього README. Мережа й облікові дані не потрібні. |

Транспорт — **stdio**: твій AI-клієнт сам запускає процес і спілкується з ним через стандартні вхід і вихід. Сервер не відкриває жодного мережевого порту.

## Встановлення

Потрібен Python 3.12+.

```bash
git clone https://github.com/MaksymDovbnia/garmin-mcp-readonly.git
cd garmin-mcp-readonly
```

Встанови через [uv](https://docs.astral.sh/uv/) (рекомендовано — він ставить точні версії залежностей із `uv.lock`):

```bash
uv sync --locked
```

або через звичайний pip (він сам підбирає версії залежностей):

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -e .
```

В обох випадках виконувані файли опиняються в `.venv/bin/`. Репозиторій називається `garmin-mcp-readonly`, але команди, які він встановлює, — `garmin-mcp` (сервер) і `garmin-mcp-auth` (одноразовий вхід).

Потім один раз увійди **у власному терміналі** (ніколи не через AI-асистента):

```bash
.venv/bin/garmin-mcp-auth
```

Скрипт запитає email Garmin, пароль (прихований) і, якщо в акаунті ввімкнено, MFA-код. Пароль використовується один раз, щоб отримати OAuth-токени, і ніколи не записується на диск, у конфіг чи змінні середовища. Токени зберігаються в `~/.garminconnect` (змінюється через `GARMINTOKENS`). Термін їхньої дії визначає Garmin; якщо сервер повідомить, що токени відхилено, запусти `garmin-mcp-auth` ще раз.

> Фіксуй те, що запускаєш. Клонуй конкретний тег чи коміт, а не рухому гілку, і перегляди приблизно 700 рядків у `src/`, перш ніж довіряти цьому сесію свого акаунту Garmin.

## Підключення до AI-клієнта

Будь-якому клієнту потрібні дві речі:

- **`command`**: **абсолютний** шлях до виконуваного файлу `garmin-mcp` у твоєму віртуальному середовищі — нижче це `/path/to/garmin-mcp-readonly/.venv/bin/garmin-mcp`, де `/path/to/garmin-mcp-readonly` — місце, куди ти клонував репозиторій. Без аргументів.
- **(необов'язково) `GARMINTOKENS`**: лише якщо токени лежать не в стандартній `~/.garminconnect`.

Назви сервер `garmin`. Після підключення попроси асистента «перевірити підключення до Garmin» (інструмент `check_connection`), щоб упевнитись, що все працює.

> **Що перевірено.** Проєкт розробляється й використовується з Claude Code та Claude Desktop на macOS. Розділи про Codex і Antigravity написані за документацією їхніх виробників, автор їх **не запускав**; якщо у твоїй версії щось відрізняється, створи issue.

### Claude Code

```bash
claude mcp add --scope user garmin -- /path/to/garmin-mcp-readonly/.venv/bin/garmin-mcp
```

`--scope user` робить сервер доступним у кожному проєкті; без нього він реєструється лише для поточного. Перевірка:

```bash
claude mcp list
```

У сесії Claude Code команда `/mcp` показує сервер і його стан. Якщо потрібна нестандартна тека з токенами, опції пишуться перед назвою сервера:

```bash
claude mcp add --scope user -e GARMINTOKENS=/path/to/token-dir garmin -- /path/to/garmin-mcp-readonly/.venv/bin/garmin-mcp
```

### Claude Desktop

Відредагуй конфіг (створи файл, якщо його немає):

- macOS: `~/Library/Application Support/Claude/claude_desktop_config.json`
- Windows: `%APPDATA%\Claude\claude_desktop_config.json`

```json
{
  "mcpServers": {
    "garmin": {
      "command": "/path/to/garmin-mcp-readonly/.venv/bin/garmin-mcp"
    }
  }
}
```

У Windows виконуваний файл зазвичай `.venv\Scripts\garmin-mcp.exe`. Після змін повністю закрий і знову відкрий Claude Desktop. Для нестандартної теки з токенами додай `"env": { "GARMINTOKENS": "/path/to/token-dir" }` поруч із `"command"`.

`manifest.json` — це експериментальний дескриптор MCPB (розширення Claude Desktop). Він проходить валідатор схеми MCPB, але автор його не встановлював, а заявлена платформа в ньому лише macOS, єдина, на якій проєкт перевірявся. Підтримуваний шлях — конфіг-файл вище.

### OpenAI Codex

Codex CLI, розширення для IDE і десктопний застосунок ChatGPT використовують один конфіг: `~/.codex/config.toml`. Додай сервер через CLI:

```bash
codex mcp add garmin -- /path/to/garmin-mcp-readonly/.venv/bin/garmin-mcp
codex mcp list
```

або відредагуй `~/.codex/config.toml` напряму:

```toml
[mcp_servers.garmin]
command = "/path/to/garmin-mcp-readonly/.venv/bin/garmin-mcp"
```

Нотатки:

- **Нестандартна тека з токенами:** `codex mcp add garmin --env GARMINTOKENS=/path/to/token-dir -- /path/to/garmin-mcp-readonly/.venv/bin/garmin-mcp`, або додай таблицю `[mcp_servers.garmin.env]` з `GARMINTOKENS = "/path/to/token-dir"`.
- **Використовуй глобальний файл.** Проєктний `.codex/config.toml` діє лише для довірених проєктів, а шлях до твого віртуального середовища особистий.
- **Стан:** у TUI Codex команда `/mcp` показує активні MCP-сервери.
- **Підтвердження:** за документацією Codex, `default_tools_approval_mode = "writes"` (у таблиці `[mcp_servers.garmin]`) питає підтвердження лише для інструментів, не позначених як «лише читання». Усі інструменти цього сервера позначені, тож цей режим не питає про них, але все одно питає про решту.
- **Таймаути:** за замовчуванням Codex дає 10 с на запуск і 60 с на виклик інструмента (`startup_timeout_sec`, `tool_timeout_sec`). Сервер стартує приблизно за секунду, а вхід в Garmin виконує під час першого виклику інструмента, а не на старті.

### Google Antigravity

У панелі агента відкрий меню `…` → **MCP Servers** → **Manage MCP Servers** → **View raw config** і додай сервер у `mcp_config.json`, що відкриється:

```json
{
  "mcpServers": {
    "garmin": {
      "command": "/path/to/garmin-mcp-readonly/.venv/bin/garmin-mcp"
    }
  }
}
```

Нотатки:

- **Де лежить файл:** документація Antigravity називає `~/.gemini/config/mcp_config.json` (глобальний, спільний для IDE і CLI) та `.agents/mcp_config.json` (для робочого простору). Відкриття з інтерфейсу дозволяє не вгадувати шлях для твоєї версії.
- **Звичайний JSON:** без коментарів і без кінцевих ком.
- **Змінні середовища:** зазвичай вони не потрібні, бо використовується стандартна тека токенів. Документація Antigravity не описує підстановку `${VAR}` у цьому файлі, а один користувач повідомляв, що значення `env` у глобальному конфігу не застосовувались. Тож якщо мусиш задати `GARMINTOKENS`, пиши літеральний абсолютний шлях.
- **Перезавантаження:** після редагування перезавантаж список серверів із менеджера MCP (`/mcp`) або перезапусти Antigravity.
- **Яка модель бачить твої дані:** результати інструментів потрапляють до тієї моделі, яку Antigravity використовує в цій розмові (дивись [Приватність і безпека](#приватність-і-безпека)).

### Інші MCP-клієнти

Підійде будь-який клієнт, що вміє запускати локальний stdio MCP-сервер. Більшість приймає ту саму форму, що й приклади для Claude Desktop та Antigravity вище: сервер із назвою `garmin`, де `command` — абсолютний шлях до `garmin-mcp`, за потреби з `env`, що містить `GARMINTOKENS`.

## Інструменти

| Інструмент | Призначення |
|---|---|
| `check_connection` | Перевіряє, що токени працюють; показує систему одиниць і модель останнього пристрою |
| `list_activities` | Останні тренування, нові першими, за бажанням із фільтром за типом |
| `list_activities_by_date` | Тренування за діапазон дат |
| `get_activity` | Одне тренування; за бажанням спліти, пульсові зони, погода та GPS |
| `daily_summary` | Кроки, пульс спокою, стрес, body battery, сон за день |
| `get_sleep` | Оцінка сну та розбивка за фазами |
| `get_hrv` | Нічний HRV відносно твоєї базової лінії |
| `get_training_readiness` | Оцінка готовності та фактори, що на неї впливають |
| `get_training_status` | Статус тренувань, гостре навантаження, VO2 max |
| `get_body_composition` | Вага та склад тіла за діапазон |
| `get_steps_range` | Денні суми кроків для запитань про тренди |
| `call_readonly` | Запасний вихід для будь-якого іншого методу `get_*` з `garminconnect` |

Дати приймаються у форматі `YYYY-MM-DD`, а також `today` чи `yesterday`.

Кожен інструмент відповідає одним компактним JSON-документом. Порожній результат — це `[]`, `{}` або `null`, а не порожня відповідь, тож клієнт завжди відрізнить «даних немає» від збою. Відповідь понад 100 КБ замінюється коротким повідомленням із проханням звузити запит.

## Чому лише читання

Читання — це весь обсяг цього проєкту. У ньому немає інструментів, які щось завантажують, редагують, логують чи видаляють, а pull request-и з доступом на запис поза межами проєкту. Це свідоме рішення:

- **Вставлений текст не змінить твій акаунт.** Назви тренувань та інші вільнотекстові поля з Garmin потрапляють у контекст моделі. Навіть якщо в одному з них колись опиняться інструкції, сервер без інструментів запису все одно не може змінити чи видалити твої дані.
- **Помилки дешеві.** Хибне припущення моделі не зіпсує твою історію тренувань.
- **Проєкт залишається придатним до аудиту.** Без шляхів запису код, який треба переглянути, невеликий (приблизно 700 рядків), а твердження «лише читання» ти можеш перевірити сам (дивись [Перевір сам](#перевір-сам)).

Як це забезпечено, окрім мітки:

- Тест проганяє кожен інструмент через клієнт-«записувач», який фіксує кожен метод, до якого звертаються інструменти, і падає, якщо хоч один не `get_*`.
- `call_readonly` відхиляє будь-яку назву методу, що не починається з `get_`.
- Тест падає, якщо будь-який метод `get_*` у встановленій `garminconnect` (з урахуванням допоміжних методів і функцій, а також позначаючи будь-яке використання клієнта, що приховало б виклик, наприклад присвоєння його змінній) може дійти до API Garmin інакше ніж через `Client.connectapi`, або дійти до запиту на запис. Другий тест перевіряє, що `Client.connectapi` жорстко прописаний на GET, а третій, що аудит охоплює кожен метод `get_*`, до якого справді може дістатися `call_readonly`.
- Ще один тест сканує код інструментів на назви викликів, схожі на запис (`upload_…`, `delete_…`, `set_…` тощо); це покриває гілки, яких поведінковий тест не виконує.
- Кожен інструмент має MCP-мітку `readOnlyHint`, і тест падає, якщо її немає. Ця мітка — підказка клієнтам, а не сам захист, але клієнти можуть нею користуватись, наприклад режим підтверджень `writes` у Codex (дивись [OpenAI Codex](#openai-codex)).

Чого «лише читання» **не** означає:

- **Це не робить твої дані приватними.** Те, що читають інструменти, стає частиною твоєї розмови з асистентом.
- **Це не зупиняє витоку через інші інструменти.** Якщо та сама сесія вміє надсилати пошту чи ходити в інтернет, текст, вставлений у твої дані, може спробувати їх використати. Обережно поєднуй інструменти.
- **Це не «нуль записів».** Оновлення токенів звертається до сервісу входу Garmin і змінює твій локальний файл токенів. Дані твого акаунту не змінюються.

Якщо тобі потрібно завантажувати тренування чи вести журнали, візьми сервер, створений для цього, наприклад [Taxuspt/garmin_mcp](https://github.com/Taxuspt/garmin_mcp), і перегляди його перелік інструментів, перш ніж вмикати.

## Приватність і безпека

### Куди йдуть дані

| Куди | Що надсилається | Навіщо |
|---|---|---|
| Garmin (`*.garmin.com`) | Обмін даними для входу (один раз, через `garmin-mcp-auth`), далі автентифіковані запити на читання | Щоб отримати твої власні дані |
| AI-клієнт, що запустив сервер | Результати інструментів (стиснуті, очищені) | У цьому й полягає призначення MCP-сервера |
| Будь-куди ще | **Нічого** | У сервері немає телеметрії, аналітики чи сторонніх ендпоінтів |

Другий рядок варто розуміти точно: **усе, що повертає інструмент, стає частиною твоєї розмови з асистентом**, а звідти потрапляє до провайдера моделі за цим клієнтом (наприклад Anthropic, OpenAI чи Google, залежно від клієнта й обраної моделі) на умовах цього провайдера. Сервер не може цього запобігти; він може лише обмежити те, що повертає. Якщо якихось даних у розмові бути не має, не став запитань, які їх отримують.

### Що сервер робить і чого не робить

- **Працює локально через stdio.** Немає порту, що слухає, і немає віддаленого хостингу.
- **Спілкується лише з Garmin.** Власний код проєкту не імпортує жодної мережевої бібліотеки. Залежність `garminconnect` звертається лише до хостів Garmin (`sso`, `diauth`, `connect`, `connectapi`, `mobile.integration` під `garmin.com`).
- **Не експортує телеметрію.** MCP SDK містить інструментацію OpenTelemetry, увімкнену за замовчуванням, але вона нічого не робить, доки не встановлено OpenTelemetry SDK чи експортер. Жодного немає (лише `opentelemetry-api`), а тест падає, якщо він коли-небудь з'явиться в дереві залежностей.
- **Ніколи не працює з твоїм паролем.** Його бачить лише `garmin-mcp-auth`, який запускаєш ти, і він іде лише до сервісу входу Garmin. У процесі сервера немає жодного шляху, що приймав би пароль.
- **Не робить запитів на запис до твого акаунту Garmin.** `call_readonly` відхиляє будь-який метод, що не починається з `get_`, а в закріпленій версії `garminconnect` кожен метод `get_*` доходить до API лише через `Client.connectapi`, який бібліотека жорстко прописує на GET (див. аудит нижче). Оновлення токенів справді звертається до сервісу входу Garmin і змінює локальний файл токенів; це автентифікація, а не зміна даних акаунту.
- **Позначає кожен інструмент як «лише читання».** Усі 12 інструментів мають MCP-мітку `readOnlyHint`, а тест падає, якщо інструмент зареєстровано без неї, тож клієнт одразу бачить, що тут нічого не змінюється.
- **Перетворює відомі помилки Garmin на короткі підказки.** Відхилені токени, ліміт запитів, недоступність Garmin і «не знайдено» повертаються одним рядком із типом винятку та не більше ніж 160 символами тексту, бо повний текст відповіді сервера може цитувати облікові дані. Інші винятки не переписуються.
- **Обмежує розмір відповіді.** Результат понад 100 КБ повертається як коротке повідомлення з фрагментом, тож сирий payload не заллє контекст моделі.
- **Стискає та очищає відповіді.** Спеціалізовані інструменти повертають невеликий набір вибраних полів. Крім того, кожна відповідь проходить через `scrub()`, який видаляє відомі ключі з ідентифікаторами (ID профілю, відображувані імена, email, ID і серійні номери пристроїв) та точний GPS. GPS можна повернути для окремого виклику через `include_location=True` в `get_activity`.
- **Не пускає токени в git.** `.gitignore` виключає теки `.garminconnect/` і `tokens/` та файл `garmin_tokens.json`, який пише `garminconnect`, тож токени не потраплять у коміт, навіть якщо вказати `GARMINTOKENS` усередині репозиторію. Усе одно перевіряй `git status` перед комітом.

### Обмеження — прочитай обов'язково

- **Скрабер працює за чорним списком.** Він видаляє *відомі* ключі. Інструменти зі стисненням (`list_activities`, `daily_summary`, `get_sleep`, `get_hrv`) повертають лише поля, обрані в коді, тож поводяться як білий список. Інструменти, що повертають очищений сирий payload (`call_readonly`, `get_training_status`, `get_training_readiness`, `get_body_composition`, `get_steps_range`, а також додатки спліти/пульсові зони/погода в `get_activity`), усе ще можуть містити ідентифікатор, який Garmin додасть під ключем, невідомим скраберу.
- **Деякі вільнотекстові та грубо-геолокаційні поля проходять**: назви тренувань, які ти ввів сам, `locationName` тренувань (зазвичай місто) і *модель* останнього пристрою.
- **Дані про здоров'я чутливі за своєю природою.** Сон, пульс і вага є особистими, навіть коли до них не прикріплено ідентифікатор.
- **Файл токенів — це облікові дані.** `~/.garminconnect` містить довготривалі OAuth-токени у звичайному JSON (`garmin-mcp-auth` обмежує права на теку до `0700`). Будь-яка програма, запущена від твого користувача, може їх прочитати. Став до них як до пароля, ніколи не коміть і не передавай.
- **Неофіційний API.** Дивись застереження на початку. Бібліотека `garminconnect` імітує офіційні клієнти Garmin під час входу, і це одна з причин крихкості.
- **Гарантія «лише читання» прив'язана до закріпленої версії.** `garminconnect` закріплена на точній версії в `pyproject.toml`, а все дерево залежностей зафіксоване в `uv.lock` (став через `uv sync --locked`; звичайний `pip install` lock-файл не враховує). Тест у наборі падає, якщо якийсь метод `get_*` у встановленій `garminconnect` може дійти до API інакше ніж через цей примітив лише для GET, тож оновлення залежності, яке ламає гарантію, буде помічене. Якщо піднімаєш версію `garminconnect`, додатково повтори аудит нижче.

### Перевір сам

Нічого з цього не треба приймати на віру. З кореня репозиторію після встановлення:

**1. У власному коді проєкту немає мережевих імпортів** (порожній вивід означає, що нічого не знайдено):

```bash
grep -rnE "import (requests|httpx|urllib|socket|aiohttp)|from (requests|httpx|urllib)" src/
```

**2. Усі хости, до яких може звертатися бібліотека Garmin:**

```bash
grep -rhoE 'https?://[a-zA-Z0-9./_{}-]+' \
  "$(.venv/bin/python -c 'import garminconnect,os;print(os.path.dirname(garminconnect.__file__))')" \
  --include='*.py' | sed -E 's#(https?://[^/]+).*#\1#' | sort -u
```

Ти маєш побачити лише `*.garmin.com` (заповнювач `{domain}` за замовчуванням дорівнює `garmin.com`).

**3. Кожен метод `get_*` доходить до API лише через примітив для GET**, з урахуванням допоміжних методів і функцій (потрібен extra `test`, дивись [Розробка](#розробка)):

```bash
uv run --locked --extra test pytest tests/test_safety.py -q -k Garminconnect
```

**4. Подивись, що відбувається під час роботи.** Увімкни мережевий монітор (Little Snitch чи LuLu на macOS, `ss`/`nethogs` на Linux), постав асистентові запитання про Garmin і переконайся, що єдині вихідні з'єднання процесу сервера йдуть до `*.garmin.com`.

**5. Або запусти весь набір тестів безпеки.** `tests/test_safety.py` покриває перевірку 3 вище, а також захист у `call_readonly`, перевірку, що кожен інструмент позначений як «лише читання», торкається лише методів клієнта `get_*` і не містить викликів із назвами на кшталт запису, правило, що `GARMINTOKENS` — єдина змінна середовища, яку читає проєкт, і перевірку, що OpenTelemetry-експортера не встановлено. Дивись [Розробка](#розробка).

## Налаштування

| Змінна | За замовчуванням | Значення |
|---|---|---|
| `GARMINTOKENS` | `~/.garminconnect` | Тека, де зберігаються й звідки читаються OAuth-токени. Посилання `${HOME}` розгортаються; нерозгорнутий заповнювач `${...}` від клієнта означає «використати стандартну теку». Жодна інша змінна ніколи не розгортається. |

Змінної для пароля навмисно немає. Щоб використовувати кілька акаунтів Garmin, увійди один раз для кожного акаунта з іншим `GARMINTOKENS` і зареєструй окремий запис сервера для кожного, з власною назвою та своїм `GARMINTOKENS`.

## Вирішення проблем

- **«No usable Garmin tokens found»** — запусти `garmin-mcp-auth` у терміналі.
- **«Stored Garmin tokens were rejected»** — токени прострочені або відкликані; запусти `garmin-mcp-auth` ще раз.
- **Сервер не з'являється в Claude Desktop** — перевір, що шлях у конфігу абсолютний і веде до виконуваного файлу у твоєму віртуальному середовищі, потім повністю закрий і знову відкрий застосунок.
- **Сервер не з'являється в Claude Code** — виконай `claude mcp list`; якщо шлях хибний, видали й додай знову (`claude mcp remove garmin`).
- **Сервер не з'являється в Codex** — виконай `codex mcp list` або `/mcp` у TUI; перевір шлях `command` у `~/.codex/config.toml` і що TOML валідний.
- **Сервер не з'являється в Antigravity** — перевір, що `mcp_config.json` є валідним JSON (без коментарів і кінцевих ком), потім перезавантаж сервери з менеджера MCP або перезапусти застосунок.
- **«Garmin rate limit hit»** — зачекай кілька хвилин і повтори.
- **«Another Garmin request is still running»** — запити до Garmin виконуються по одному, а виклик чекає своєї черги не довше 30 с; повтори за мить.
- **Результат із `"truncated": true`** — відповідь перевищила 100 КБ і була замінена повідомленням; попроси менше (коротший діапазон дат або одне тренування).
- **Вхід не вдається або спрацьовує обмеження частоти** — Garmin іноді обмежує чи перевіряє автоматизовані входи. Зачекай трохи й повтори, а якщо просить — пройди MFA.

## Розробка

```bash
uv sync --locked --extra test
uv run pytest tests/ -q
```

або без uv:

```bash
.venv/bin/python -m pip install -e ".[test]"
.venv/bin/python -m pytest tests/ -q
```

Тести покривають розбір дат, скрабер, стиснення тренувань (зокрема вкладений payload одного тренування), обгортку з підказками для помилок, визначення теки токенів, паралельність (один вхід, один запит за раз), формат відповіді з одного JSON-блока, обмеження розміру відповіді і твердження про безпеку з цього README (кожен інструмент «лише читання» і торкається лише методів `get_*`, захист `call_readonly`, відсутність мережевих імпортів у коді проєкту, з середовища читається лише `GARMINTOKENS`, `get_*` доходять до API лише через примітив для GET). Мережа й облікові дані не потрібні. CI запускає їх при кожному push і pull request.
